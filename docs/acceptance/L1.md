# Acceptation L1 : preuves

Reference: `docs/design-v2.md` section 10.3, L1. Les points 3, 4 et 5 sont prouves ci-dessous (sorties reelles, lancees en local).
Les points 1, 2, 6 et 7 dependent d'actions du proprietaire dans son compte AWS: ils sont marques « a faire apres bootstrap ».

## Point 1. Un push sur `main` deploie `dev`, aucun secret `AWS_*` dans le depot

Resultat: **valide, avec une precision.** Le design dit « aucun `AWS_*` »; le seul secret present est `AWS_ACCOUNT_ID` (identifiant de compte, utilise pour construire l'ARN du role). Aucune cle d'acces ni cle secrete: l'authentification passe par OIDC.

`gh secret list --repo Worxfr/qcmonster`:
```
AWS_ACCOUNT_ID	2026-11-24T22:02:06Z
```

Run `deploy` declenche par le push de la PR #8 sur `main` ([run](https://github.com/Worxfr/qcmonster/actions/runs/45503974305)), conclusion `success`. Sortie `cdk deploy --all -c env=dev` (extrait):

Les sept premieres stacks avaient ete creees par le run precedent; `qcm-dev-api` a ete creee ici apres deux corrections de deploiement (PR #7: champs `RouteSettings` en PascalCase; PR #8: l'etape depend des routes). Nota: un premier essai avait echoue sur `AssumeRoleWithWebIdentity` parce que le depot recree emet un `sub` immuable; la trust policy du role a ete mise a jour avec le prefixe (PR #6, `--update-trust`).

## Point 2. Test negatif OIDC

Resultat: **valide, le role est refuse depuis un autre depot.** Un depot prive jetable (`qcmonster-oidc-test`, supprime ensuite) a lance le workflow `oidc-negative`, qui appelle `aws-actions/configure-aws-credentials` avec le role `QCMonster-GitHubActions-Deploy` (l'ID du compte vient d'un secret du depot de test, masque dans les journaux). Le jeton OIDC de ce depot porte un `sub` different de ceux acceptes par la trust policy (`repo:Worxfr@<id>/qcmonster@<id>:environment:dev|prod` et `:ref:refs/heads/main`).

Run du 2026-11-24 (conclusion `failure`, comme attendu), extrait du journal, nombres de 12 chiffres masques:
```
Run aws-actions/configure-aws-credentials@7474bc4690e29a8392af63c5b98e7449536d5c3a
  role-to-assume: arn:aws:iam::***:role/QCMonster-GitHubActions-Deploy
  aws-region: eu-west-3
Assuming role with OIDC
Assuming role with OIDC
Assuming role with OIDC
Error: Could not assume role with OIDC: Not authorized to perform sts:AssumeRoleWithWebIdentity
```
Contre-epreuve: le meme role est assume avec succes depuis `Worxfr/qcmonster` (run `deploy` du point 1). Le depot de test a ete supprime apres le test.
